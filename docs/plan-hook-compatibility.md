# 本机钩子兼容接入

日期：2026-10-25。状态：已实现并完成本地验证。

## 目标

个人启用推送保护时保留团队的 Husky、项目钩子和部署工具生成的钩子。检查、超限确认和原 pre-push 由同一个串行入口执行，检查失败时原上传钩子不运行。

## 实施计划

- CLI：`hook install --compatible` 在 Git 元数据目录安装本机调度器，保存原路径和本机配置；其他标准钩子转发到原目录。普通仓库保留已有仓库包装层和可选全局模式。
- 生命周期：重复安装不嵌套；`hook repair` 在配置被工具重设后重新接入当前目录；卸载只恢复仍由 YunBox 持有的配置，保留后续用户修改。登记文件或调度器被修改时保留现场。
- 诊断：区分已接入、待兼容、保护被覆盖、调度器损坏、原目录缺失；Husky/node_modules 缺失提示先安装项目依赖，其他缺失提示检查遗留配置。清理只针对本机失效配置，不能猜测或改动团队脚本。
- 客户端：单独显示全局开关与当前仓库状态；按客户端已知仓库统计保护、待兼容、被覆盖及读取失败数量，不声称扫描了整台电脑。
- 验证：真实 Git 钩子及 push、完整参数/stdin、原检查失败、其他事件、Husky 目录重建、worktree、幂等、恢复和用户修改保护；CLI 检查、Swift 测试和应用构建；双语使用指南、更新日志和本地化。

## 设计边界

- 不修改 `.husky`、项目脚本或 `node_modules` 内容；有工具官方扩展入口时仍可手动串联，本机调度器提供通用接入。
- 不执行项目的依赖安装脚本，也不自动清理缺失目录配置。缺失目录不当作“无需执行原钩子”，推送失败并提示修复。
- 相对路径保持 Git 在每次钩子调用时的工作目录语义，支持共享配置的 linked worktree；启用 `extensions.worktreeConfig` 时使用当前 worktree 的配置。
- 独立配置的上传钩子仍由其管理器保证顺序；`--no-verify` 的 Git 语义不变。未发现的仓库不计入客户端覆盖率。


## 验证结果

- `pnpm build`（含双语文档站）、`pnpm lint`、`pnpm typecheck` 通过；`pnpm test` 320 项通过、8 项按环境条件跳过。
- 12 项兼容钩子测试覆盖串行拒绝、完整 stdin/参数、原检查退出码、其他事件、Husky 布局和路径重设、继承配置、多条配置、缺失目录、worktree、别名递归、原脚本改动、Git 配置锁导致的安装回滚。真实 Git LFS 用例证明拒绝时远端无对象，放行后 push 和全新 clone 恢复相同文件。
- `yunbox init` 回归覆盖已接入的 Husky 用户脚本，保留团队脚本和调度器；无法识别 LFS 调用时提示维护者处理。
- Swift 测试 53 项通过；`script/sync_strings.sh --check` 校验 508 条文案全部有英文；`script/build_and_run.sh --verify` 构建并启动开发包，实际窗口核验全局开关、当前仓库状态、已知仓库计数和滚动布局。
- 全量测试发现既有历史迁移用例两次读取当前时间却假定排序不变，改为使用同一时间戳，消除跨毫秒偶发失败；未改变历史记录行为。
- 未修改本机真实项目的钩子配置；所有安装、修复和卸载用例在隔离 HOME / Git 仓库运行。尚未进行 Windows 真机或特定部署工具私有扩展入口的验收。
